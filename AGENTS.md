# Repository Guidelines

## Project Structure & Module Organization
The game lives in `index.html` (HTML, embedded CSS, rendering, input, menu, shop, and game loop) plus `game-logic.js` (extracted logic for the starter platform, enemy patrol, and sprite-mask collision). `index.html` keeps a fallback copy of that logic and must still boot when `game-logic.js` is missing. Tests are `game-logic.test.js` and `browser-smoke.test.js`; `screenshots/` holds images, and `.github/workflows/` deploys the site to GitHub Pages.

The game is installable as a PWA: `manifest.webmanifest`, the service worker `sw.js`, and `icons/` (generated by `scripts/generate_icons.py`; edit the script, not the PNGs). When adding a file the game needs at runtime, add it to `appFiles` in `sw.js` (and bump `cacheName`) and to the copy step in `.github/workflows/deploy-pages.yml`; otherwise the installed app breaks offline or the file is missing on Pages. Keep all URLs relative, because Pages serves the site under `/pixelrun/`.

## Build, Test, and Development Commands
There is no build step. Serve the repository root with a simple static server:

```bash
python3 -m http.server 8000
```

Then open `http://localhost:8000/index.html`. Run the tests with `npm test` (Node's built-in test runner; the browser smoke test needs `google-chrome` or `CHROME_BIN` and is skipped otherwise).

## Coding Style & Naming Conventions
Use 4-space indentation in HTML, CSS, and JavaScript blocks to match the existing files. Prefer `const` for stable bindings and `let` for mutable state. Keep JavaScript identifiers in `camelCase` (`generateWorld`, `updateRockWall`) and reserve `UPPER_SNAKE_CASE` for true constants only if they are introduced consistently. Preserve the current structure of small helper functions and direct event listeners instead of adding framework-style abstractions.

## Testing Guidelines
Run `npm test`, then smoke-test in the browser: start the game, move, jump, attack, collect coins, use the shop, and confirm that score and audio behavior still work. Input changes must work with both the keyboard and the on-screen touch controls (use DevTools device emulation or a real phone). Game logic runs at a fixed 30 ticks per second; keep per-tick state changes out of drawing code.

## Commit & Pull Request Guidelines
Follow a simple imperative commit style such as `Add fireball cooldown tuning` or `Refine enemy collision checks`. Keep commits focused on one change. Pull requests should describe gameplay impact, list the files changed, and include screenshots or short recordings for visual changes.

## Configuration & Asset Notes
The game currently depends on externally hosted audio URLs. Avoid introducing secrets or environment-specific values into the files. If offline reliability becomes important, replace remote media with versioned local assets.
